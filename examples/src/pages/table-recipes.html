Table recipes

One feature per section. Each grid below is configured for exactly that feature and nothing else, over the same eight rows, and each snippet is complete — copy a block and it runs.

The Table plugin page is the opposite of this one: everything at once, the way a real screen uses it. That shape is right for judging whether the parts belong together and wrong for learning any one of them. The written reference is docs/table-plugin.md.

1. The smallest grid that works

Columns in, <Table> props out. Nothing is on by default — no filters, no selection, no paging, no actions. formatDate is what a timestamp column calls; without one, values are stringified.

2. A cell type of your own

Register a renderer against a name and any column may ask for it by type. Anything the column entry carries beyond the base keys — currency here — arrives at the cell as column.options, untouched. A Weave component works in the same slot with no wrapper; these two are plain functions because there is nothing to compose.

3. Row actions — buttons, menu, or only the menu

One array, two renderings. Right-click a row for the menu. visible drops an action for rows that do not qualify (Send is only on the ready ones), disabled renders it inert (Lock), and showIn: 'menu' keeps one out of the row whatever the table-wide setting says (Delete).

actionsIn: {{ actionsPlacement() }} · last: {{ actionsLast() }}

4. Global actions

The table-wide controls live in the grid's own header, not on a strip above it. The list is a getter and every predicate is a getter, so an action can grey out, appear and go pressed without the grid being rebuilt. The last entry is not a button at all — an action may render its own control, and that one counts the ready rows.

last: {{ globalLast() }}

5. Filters

A control per column, in a second <thead> row, so the boxes line up with their columns whatever the widths are. Type and press Enter; emptying a box applies at once. Amount sets searchDisabled and gets none.

The plugin filters nothing itself — it reports a query. This page plays the server, which is exactly where your own fetch would go.

query: {{ filterQuery() }}

6. Selection — checkbox and click, one set

Click selects one, Ctrl (Cmd) adds or removes one, Shift extends from the last row touched, and the checkbox does its own thing without disturbing the rest. The anchor does not move on a Shift-click, so a range can be stretched and shrunk without starting over.

8. The columns menu, and what it saves

Right-click a column header. Switch one off, or drag a grip to move it — a line shows where it will land, and the grip works from the keyboard with Space, the arrows, then Space. Drag a column edge to resize.

The panel's markup is yours; the columnsPanel action only adds the reordering, and it reads the order from the DOM at drop time so what it reports is what is on screen. Ready is hideInMenu — listed and movable, not switchable. secret is hidden and appears nowhere.

9. Roles

One checkRole, checked in three places: columns, row actions, global actions. A column the viewer has no role for is dropped, not hidden, so it cannot be switched back on from the columns menu. Switch the role and both Secret and Purge come and go.

role: {{ roleName() }}

10. Enums that arrive late

A column file ships with the application; its enum tables come from the server, reliably after the first page of rows in at least some races. Read through a getter, a late arrival fills the cells and the filter. Read once, that column stays blank for the life of the grid with nothing reporting it — which is why the built-in enum cell is a live node rather than a string.
